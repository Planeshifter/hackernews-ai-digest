### GPU-unlock: FP/BF16 instruction issue rate on Nvidia 3000's cards

#### [Submission URL](https://github.com/Zagitta/gpu-unlock) | 324 points | by [fragebogen](https://news.ycombinator.com/user?id=fragebogen) | [74 comments](https://news.ycombinator.com/item?id=50219700)

**A Linux kernel module that lifts the FP/BF16 issue-rate cap on consumer Ampere cards**, so GeForce 3000-series GPUs run tensor math at the rate of their professional equivalents. On a 3090 Ti at 450 W, dense 8192³ GEMM with FP32 accumulation goes from 87.5 to 157.4 TFLOPS in BF16, 87.5 to 118.4 in FP16, and 42.6 to 82.6 in TF32.

It builds on the CMP unlocker's V67/PLM technique and the pre-driver timing of an earlier UEFI approach. The module writes the speed selectors (SS0 `0x88888888`, SS1 `0x8`) and performs a function-level reset before the stock NVIDIA driver binds the card. It is neither a UEFI app nor a patched driver, so you don't re-patch on every driver release. It targets GA102, GA103, GA104 and GA106.

**User reports are the evidence here.** Results are crowd-sourced per card, and the benchmarks differ per report:
- **Unlocked:** 3090 Ti, 3090 (+25–67%), 3080 10 GB and 20 GB, 3070, and 3060 12 GB (about +80%).
- **Doesn't work:** one OEM 3080 Ti 20 GB completes the unlock but stays at half BF16 rate.
- **Untested or no reports:** the 3070 Ti (the unlock worked from a UEFI port on Windows) and GA103.

The lowest gain, +25%, comes from cards capped at 225 W, so the power limit matters.

**Only matrix-heavy work benefits.** LLM prefill gains 14–36%, and diffusion and FlashAttention speed up. Decode is memory-bandwidth-bound and INT8 is unchanged, so both stay flat. Reports that compared outputs found them bit-identical before and after. Multi-card setups (up to four), display-driving cards, and vfio-pci passthrough all have reports.

**Setup:** run `make install`, which detects Arch, Debian/Ubuntu or Fedora/RHEL, builds a package, and puts the module and its firmware into the initramfs. Then add `gpu_unlock.targets=all` to the kernel command line. The build downloads pinned NVIDIA/CachyOS inputs over HTTPS and checks their SHA-256. The distributed source and packages contain no NVIDIA archives or generated firmware.

The catch: this deliberately writes hardware registers that NVIDIA gated off, and the results span a wide range across cards. Test your own card before relying on it, and note that a card driving the display goes blank briefly at boot.

### Making My Blog Readable by AI Agents

#### [Submission URL](https://deallocatedobjects.com/posts/making-my-blog-readable-by-ai-agents) | 33 points | by [ingve](https://news.ycombinator.com/user?id=ingve) | [8 comments](https://news.ycombinator.com/item?id=50225443)

**A static nginx blog can serve markdown to agents with one `map` and a rewrite**, no framework needed. Send `Accept: text/markdown` to any post URL (or append `.md`) and you get the post as plain markdown with YAML frontmatter (title, canonical URL, author, dates, description) instead of HTML.

The negotiation hinges on two details. Every response carries `Vary: Accept`, so intermediate caches don't serve HTML to an agent or markdown to a browser. The `.md` responses also send a `rel="canonical"` Link header to the HTML page plus `X-Robots-Tag: noindex`, so Google doesn't treat them as duplicate content.

The rest of the evening's work is mostly generated files:

- **`/llms.txt`**: blog summary, how to get markdown, feed locations, citation preference, and every post with a markdown link and one-liner. A Link header on every response points to it. `/llms-full.txt` bundles all posts into one ~225 KB file, and `/index.md` is the homepage.
- **`robots.txt`**: explicitly allows GPTBot, ClaudeBot, PerplexityBot, Google-Extended and about a dozen others, with `Content-Signal: search=yes, ai-input=yes, ai-train=yes`. The author wants citations; a product site might not.
- **Feeds**: the Atom feed gains summaries and a markdown alternate link, and a new JSON Feed uses a custom `_markdown_url` key per item.
- **Metadata**: descriptions, canonicals, Open Graph/Twitter tags, and JSON-LD (BlogPosting, breadcrumbs, WebSite/Blog/Person) on every page.
- **IndexNow**: a ~30-line script pings Bing on publish. Google doesn't participate, but Bing's index feeds several AI search tools.

The cleanup of 2014-era problems is the most reusable part. Stored descriptions had paragraphs mashed together ("…your app.The RevealWhat do I mean…") and some contained raw `<img>` tags, so summaries are now built from rendered text. `maximum-scale=1` was blocking pinch-zoom and is gone. With no `og:image`, X and Threads grabbed the first image on the page, an old banner, so each post now has a 1200x630 card.

The pitch is that none of it is hard. The post itself is fetchable as markdown with the same curl trick.

The thread's main argument is that the whole exercise may be aimed at readers who aren't there. The top comment cites two log-analysis studies. One found no sign that GPTBot, ClaudeBot or similar crawlers request or prioritize `.md` content, even when it's listed in `llms.txt`. The other covered 50 sites over 200+ days and logged zero `/llms.txt` requests from any major AI user-agent. A later commenter pointed to a third experiment where no bot touched the file in three months.

Anecdotal evidence pushed back only weakly:
- One user said their agent tool (oh-my-pi) once read a site's `llms.txt` during research.
- Another gets the odd attempt on a personal site, but mostly bots just fetch `robots.txt`.

Nobody offered data showing real adoption. The open question is whether `Accept: text/markdown` negotiation works better than `llms.txt`, since it serves interactive agent fetches rather than crawlers. The thread didn't test that.

Two other points came up:
- **robots.txt gotcha:** Groups don't merge. If you give GPTBot or another named bot its own group, it stops obeying `User-agent: *`, so every disallow line has to be repeated in each named group.
- **Ethical objection:** One commenter asked why you'd help AI companies take your writing for free. A reply argued that a human is usually still on the other end of Claude or ChatGPT, trying to solve a problem or learn something, so serving them isn't just feeding a scraper. The author's stated goal of getting citations was not weighed directly.

One commenter also dropped a bare link to agents.md, with no discussion.

The repo shows signs of being generated from an API spec (a `generated` directory and a `.castiron` stats file), so expect command coverage to track the API closely.
