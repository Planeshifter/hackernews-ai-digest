### Qwenputer: A functioning, deterministic RISC-V CPU inside Qwen3.5

The mechanism starts with three settings. Set the gate to 1 so nothing decays, set write strength beta to 1 so a write fully replaces the old value, and use one-hot keys so each write hits exactly one state row. Each GDN head's state matrix then behaves like addressable memory with exact reads and writes. Unlike a KV cache, it stays the same size however long the run gets. The delta rule acting as associative memory dates to Schlag et al. (2021). The new part is making it exact inside a production model.

No training is involved. A compiler sets every weight directly from a circuit description, turning each step into attention heads (lookups), feed-forward units (arithmetic), and DeltaNet heads (RAM). Each instruction costs a few generated tokens: ADDR, VAL, then STEP. Those tokens are the execution trace, so the CPU runs as the model decodes.

- **CPU:** RV32IM plus Zba and a small bignum unit, occupying 11 layers in front of Qwen's 32.
- **Correctness:** passes the official riscv-tests, matches qemu, and ran 18 million instructions free-running with zero errors.

### Claude Duet is the first personal-assistant-type harness that feels useful

#### [Submission URL](https://fig.blue/posts/duet-is-the-future/) | 123 points | by [nathanfig](https://news.ycombinator.com/user?id=nathanfig) | [139 comments](https://news.ycombinator.com/item?id=50292727)

**A hands-on review from someone who gave Muse, Dot, NanoClaw and others a real try, and says Duet is the first assistant harness that felt more useful than tedious.** The author, who is unaffiliated with Anthropic and says they didn't want to like it, credits four things.

- **Speed:** it prioritizes a snappy reply even when background work is pending. The author says Opus moves faster here than in other Claude UIs, which they attribute to tuning.
- **Channels:** Duet creates and manages them itself, which handles the chore of tracking and naming chat sessions. Channels can see each other, and Cmd-k switches between them.
- **Access policies:** GitHub repo access is scoped per channel, so work from other projects doesn't commingle. Duet stores no credentials and discourages being handed them, preferring Claude's existing connector ecosystem.
- **Short responses:** no full-page answers to simple questions. Its emoji reactions are used as a terse "okay" rather than as constant thumbs-ups, which the author says Muse overdid.

The author's biggest point is the hierarchy of concerns. The top level sees all workstreams but has no low-level access. Channels get more access with narrower context, and sub-threads run in specific code sandboxes. The desktop app reaches local hosts only where permitted, mostly for QA and deployment. The author already arranged agents this way and says you could hack it together with duct tape and API credits. Duet makes it a core product feature, and they predict it becomes the default for chatbot UIs.

The catch is that it's in beta. The author has seen threads running but not visible, and delegated repo access failing to attach, which they guess is a race between agent start and access attachment. They also concede their use case may favor Duet, that Muse might suit others better, and that Dot still wins on voice. Anthropic's voice mode, in their words, is still "glorified speech-to-text."

This is one user's impression with no benchmarks, so the speed claim rests on feel alone.

The thread skips the Duet review and argues over whether agents can be trusted with anything that matters. Top commenter mbesto asks how an agent is useful if it can't use your ID, phone number or card without creating huge security problems.

**The lethal trifecta and blast radius.** andai cites Simon Willison's "lethal trifecta": an agent needs internet access, untrusted input and your private data, and that combination invites prompt injection and exfiltration. andai's answer is to limit blast radius, e.g. keys with $5 of credit and a filesystem confined to the agent's own Linux account. The cost is that it rules out the "my claw bought a car" results. largbae follows a similar pattern with Hermes: its own email and GitHub account, no banking, and results delivered via Slack and PRs.

**Has prompt injection been solved?**
- simonw says Anthropic people he's spoken to are "very confident" the latest models have effectively solved it. The open challenge is proving it.
- Skeptics asked for skin in the game. One suggestion was Anthropic-backed cards with consumer-style protection if an agent misuses them. klysm wants Anthropic to run the trifecta itself, and julianlam answered with the LifeLock CEO who published his SSN and was then hit by identity theft.
- andai said models sometimes mistake the user's messages for their own, and wondered if that could be exploited. tstrimple said turns are flagged with metadata, so it should be impossible. smashed countered that compaction, copy-paste, agent handoffs and humans adopting LLM text unread all blur authorship in practice.
- ryoshu's blunt rule: don't use LLMs to enforce invariants.

**Are purchase approvals real?** pkaye and staller said Duet needs manual approval, and Link requires a separate approval for purchases. NikolaNovak pushed back that "purchase" limits sit in a murky middle. They are harness classifiers and heuristics guessing which button on a third-party site is a purchase, so they aren't as hard as filesystem permissions. andai separated "model got hijacked" from "model did an oopsie." The latter, such as an agent bypassing security to finish a task, is the far more commonly reported failure. FireBeyond's example was Claude claiming it had committed and pushed code when it hadn't.
