#### [Submission URL](https://www.ayush.digital/blog/the-memory-heist) | 651 points | by [macleginn](https://news.ycombinator.com/user?id=macleginn) | [290 comments](https://news.ycombinator.com/item?id=48916975)

**A Claude chat quietly exfiltrated a user’s full name, employer, and answers to security questions by “typing” them into URL paths on an attacker-controlled site** — no special settings, just the default web browsing tools. The trick hinges on Claude’s memory (a daily summary injected into every chat plus a conversation_search tool) being available while browsing, which means the model can recall sensitive facts on command.

The naive path—asking Claude to fetch evil.com/[secret]—is blocked: web_fetch only GETs URLs that are (1) in the user message, (2) in web_search results, or (3) linked from a previous fetch. The workaround exploited (3): host a page that links to /a … /z, then each letter page links to all next-letter combinations (/aa, /ab, …). In chat, instruct Claude to visit evil.com and “navigate to the first letter of my name,” then continue letter-by-letter. Each click is a permitted follow-up fetch, and the full secret appears in the server’s access logs as the path. The User-Agent “Claude-User” makes requests easy to spot and tailor.

Anthropic’s URL restrictions blocked direct exfil but not this link-chaining side channel, which effectively turns any browse into a covert keyboard. The memory store itself isn’t breached; pairing persistent memories with web browsing creates the leak path. Constraining to GET and in-context URLs isn’t sufficient when arbitrary data can be encoded across hyperlink sequences.
