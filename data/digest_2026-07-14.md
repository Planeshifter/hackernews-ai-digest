### The Agentic Loop: Three loops in a trench coat

#### [Submission URL](https://www.bobbytables.io/p/the-agentic-loop-three-loops-in-a) | 86 points | by [btables](https://news.ycombinator.com/user?id=btables) | [28 comments](https://news.ycombinator.com/item?id=48907672)

**LLM chat APIs are stateless, so an “agent” is really an orchestration of three loops that resend full context, execute tools, and gate actions.**
- **Inference loop:** sends system/user/assistant messages and available tools to a chat-completions API each turn, appends responses to persistent chat history, and decides whether to continue. Because providers don’t track prior state, you must include the entire conversation every call, which is why long threads burn tokens.
- **Tool loop:** executes the model’s inferred tool calls (there can be multiple per turn), then feeds back structured tool results into the chat. Be defensive: tool names/params are just inferred text and can be hallucinated. Always correlate via the provider’s tool_call_id (or tool_use_id); omit it and the next request errors. Some APIs don’t model tool errors—return them as content (e.g., XML-tagged) if needed; Anthropic exposes an is_error flag.
- **Human (safety/sanity) loop:** optional but useful when you want control; it doesn’t have to be a human, but it’s the supervisory gate over actions and outcomes.

The practical takeaway: treat agents as IO/state machines—persist messages, validate and correlate tool calls, and surface explicit error signals—since the LLM alone is just “a brain in a jar.” Streaming complicates the plumbing, but this three-loop shape holds.

- **The "tail-chasing" problem:** Skepticism emerged around the efficacy of letting complex agent loops run independently. Commenters warned that deep, automated feedback cycles often devolve into "depth-first development" and indefinite token burn, producing highly active "superpowered vibecoding" rather than reliable software architecture. 
- **Visualizing the architecture:** Disagreement arose over the orientation of the author's diagram. Several readers argued that the high-frequency inference loop should be represented as the tightest, innermost core rather than the outermost boundary. The author noted they drew it that way because they visualize the system from the outside in.
- **Implementation contexts:** When a user asked how to execute this three-loop strategy using a standard $20/month Claude web subscription, developers clarified a core distinction: the article describes the systems-level plumbing required to build an API harness from scratch, not a prompting strategy for consumer end-users (whose chat interfaces already abstract these mechanics away).
- **Infinite recursion:** Others pointed out that three loops is an arbitrary floor. Because any software abstraction is a cycle of instruction execution, sophisticated agent harnesses often become a "token-fueled katamari ball" of deep, dynamic loops within loops.
