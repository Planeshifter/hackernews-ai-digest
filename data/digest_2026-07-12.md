### Migrating a production AI agent to GPT-5.6: 2.2x faster, 27% cheaper

#### [Submission URL](https://ploy.ai/blog/migrating-a-production-ai-agent-to-gpt-5-6) | 246 points | by [brryant](https://news.ycombinator.com/user?id=brryant) | [115 comments](https://news.ycombinator.com/item?id=48882716)

**In Ploy’s homepage-rebuild eval, GPT-5.6 Sol beat Claude Opus 4.8 on speed (3m42s vs 8:00), cost ($2.22 vs $3.06), and quality (0.970 vs 0.936) while using ~half the output tokens (17.1K vs 33.0K).** It also wrote less code; one matched pair saw Opus emit a 17,957‑char globals.css with 174 CSS variables, while GPT-5.6 used 2,508 chars and 45 vars for a comparable, sometimes better, render.

The catch was the migration work. Their first cross-model run exposed eval-harness bias: GPT-5.6’s parallel tool calls blew past Opus-sized budgets, batched file reads weren’t supported (which GPT-5.6 uses often), and an omitted minScore silently defaulted to 1.0, “failing” defensible designs. They fixed the harness before trusting any pass rates.

- Tool-call divergence broke reads. Ploy’s code tool has 25 top-level params; Claude sends only the few it uses, but GPT-5.6 sent all 25 on 100% of 6,635 observed calls, inventing values like offset: 0 and timeout: 120000. The file-read path treated offset: 0 as real, so 52–64% of GPT-5.6 reads returned empty while still reporting success: true, prompting more calls and worse results. Prompt directives (“omit unused parameters”) and OpenAI strict mode didn’t change this, and adopting strict mode would have meant stripping pattern/format/array-bound validation. The fix was a schema transform at the provider boundary: rewrite optionals as required-but-nullable (anyOf: [T, null]) so the model can emit nulls; strip nulls before normal validation so tool implementations stay unchanged.
- Provider assumptions leaked elsewhere too. Differences in how models fill tool arguments, cache prompts, and replay reasoning between turns required updates to the eval harness, tool schemas, prompt caching, and reasoning-replay logic.

Design-wise, GPT-5.6 tends to converge on clean, tightly gridded layouts unless strongly steered; Ploy’s design/engineering teams tightened the steering to hit brand-adherence requirements. The broader lesson: when swapping a production agent’s frontier model, your harness and schemas matter as much as the model choice—triage traces, adapt to provider-specific call shapes, then measure.

- Multi-step tasks: Claude Code sometimes wins overall by batching tool calls into fewer requests; in one run it beat OpenCode. But on a newer model rerun, the same task took roughly 298k tokens for Claude Code vs 133k for OpenCode, flipping the result.

A local Meridian gateway envelope (~6,200 tokens on Sonnet, ~3,500 on Fable) was measured and subtracted; payload captures are ground truth.

The takeaway for production agentic setups: harness overhead and cache strategy can dominate total cost and shrink usable context far more than model choice alone.

### Flash-MSA: Accelerating Million-Token Training with Sparse Attention Kernels

#### [Submission URL](https://nanduruganesh.github.io/flash-msa/) | 39 points | by [rawsh](https://news.ycombinator.com/user?id=rawsh) | [5 comments](https://news.ycombinator.com/item?id=48884618)

**Only the proxy forward pass is quadratic in sequence length; everything else caches block indices and runs linear-time**, which is how these kernels make million-token training practical on H100/B200 without blowing up memory or registers.

What shipped: performant, open-source Minimax Sparse Attention (MSA) training kernels in CuTeDSL targeting NVIDIA Hopper and Blackwell. Unlike most public sparse-attn code that focuses on inference, this implements a full forward/backward with fused gradients for proxy and main attention.

Key ideas:
- **Blockwise sparsity (128-token blocks) via proxy max-pooling**, so you cache block indices once and reuse them through backward instead of tracking per-token indices.
- **GQA-based main attention (not MLA)**, plus group-wise proxy heads that can pick different KV subsets per group — a formulation friendlier to teams that don’t train with MLA and likely more expressive than summing across the whole layer.
- **Streaming top-k in registers during proxy forward**, skipping LSE accumulation there and cheaply recomputing proxy LSE over the sparse activations in backward to reduce register/shared-mem pressure.
- **Block-sparse main attention reparameterized into varlen flash** (borrowing the MoBA trick) for an efficient forward.
- **Fused proxy+main backward** scheduled by inverting the cached mapping from queries→blocks to blocks→queries, maximizing KV block reuse; Q/K/V tiles are shrunk to fit register budgets.
- **KL loss backprop without materializing both distributions**: compute gradients atomically from p (main) and p_px (proxy) to avoid extra shared-memory traffic while remaining equivalent to the full KL term.

Caveats and context: this is an unofficial implementation built and tested on rented H100/B200s; the author references FA4, MSA inference, and Codex, and positions this as the first performant OSS training path for MSA rather than a MiniMax-endorsed release.

### The One-Step Trap (In AI Research)

**Iterating imperfect one-step world models snowballs error, and in stochastic settings the rollout tree makes computation blow up exponentially with horizon.** Sutton calls this the one-step trap: assuming you can learn only one-step predictions (e.g., a transition model) and reliably “roll them out” for long-term consequences, as if using physics or a perfect simulator. The grain of truth—perfect one-step accuracy would imply perfect long-term predictions—almost never holds, so rollouts are both inaccurate and intractable in practice. He argues one-step world models are “hopeless yet appealing,” despite their widespread use in POMDPs, Bayesian analyses, control theory, and compression-leaning theories of AI. The proposed remedy is temporally abstract modeling—learning longer-horizon predictions directly via options and GVFs (with pointers to Options, Horde, and reward-respecting subtasks).

The thread splits into two distinct tracks: the practical realities of high-level RL planning, and a counter-argument drawn from recent LLM behavior.

Those on the reinforcement learning side validate Sutton's critique, framing the problem as the "tyranny of the specific." They note that long-horizon planning requires temporal abstractions—much like a traveler focuses on flight legs rather than simulating every traffic light on the way to the airport—to avoid generating exponentially massive search graphs. One practitioner highlighted their recent research (arXiv:2410.05364) using multi-step diffusion models as a direct architectural alternative to one-step rollouts. 

Conversely, others challenge the underlying assumption of compounding error by pointing to LLM test-time scaling. They note that Yann LeCun made identical first-principles arguments against LLMs, yet newer reasoning models demonstrably self-correct by emitting "Wait" tokens (as in S1) to rethink their logic. Skeptics pushed back on this comparison, arguing from recent experience that these forced self-correction tokens frequently cause an LLM to steer an initially accurate chain of thought directly off a cliff.
