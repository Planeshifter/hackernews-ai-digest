### AI-Generated GitHub Copilot “Autofix” Allowed Compromise of Snowflake's Jira

#### [Submission URL](https://www.wiz.io/blog/red-agent-snowflake-copilot-cicd-bug) | 414 points | by [galnagli](https://news.ycombinator.com/user?id=galnagli) | [152 comments](https://news.ycombinator.com/item?id=49331423)

**An attacker could get code execution in a GitHub Actions runner just by opening an issue, then siphon Snowflake’s Jira token**, because a merged workflow change interpolated the attacker-controlled issue title directly into a shell run block; Copilot was a co-author that checked the PR and marked it all‑clear, and GitHub Advanced Security also didn’t flag it. Wiz’s autonomous “Red Agent” found and exploited the bug in snowflakedb/snowflake-connector-net’s jira_issue.yml, which triggers on issues: opened (so any GitHub user could fire it) and used sed escaping after GitHub’s template expansion. A single quote in the title broke out of echo '…', enabling arbitrary commands.

The supposed guardrail, if: (github.event_name == 'issues' && github.event.pull_request.user.login != 'whitesource-for-github-com[bot]'), was ineffective because pull_request is null on issues events, making the condition always true. Red Agent initially hit a bash EOF error when using # to comment, then autonomously adapted the payload to close TITLE=$(...) with ; echo ' and exfiltrate via curl to an out‑of‑band listener. Within seconds, a runner at 20.106.182.197 (Azure) sent base64-encoded Jira credentials; the token authenticated as qa@snowflake.net to snowflakecomputing.atlassian.net with read access across engineering, security compliance, and bug bounty projects.

The vulnerable pattern went live June 18, 2026 via PR #1218, which replaced a previously safe env + jq --arg approach with direct ${{ github.event.issue.title }} interpolation. Copilot Autofix’s documented change in that PR was to a different workflow (jira_close.yml), and the post notes it’s unclear whether the vulnerable edit was AI-authored—only that Copilot co-authored/checked and didn’t catch the flaw. Wiz disclosed on June 23; Snowflake restored the safe parsing pattern the same day, revoked the token, and audit logs showed only Wiz activity during the five-day window.

The transferable lesson: CI workflows are code and must treat untrusted metadata as data—quote before expansion (env + jq --arg), avoid templating into shell, and ensure event-condition logic is actually evaluated for the right payload. AI “autofix” and static scanners are not sufficient review gates for shell injection paths.

The discussion largely diagnoses the vulnerability as a structural failure of GitHub Actions rather than just an AI hallucination. Commenters argued that embedding Bash inside YAML creates a perilous custom DSL, compounded by GitHub’s decision to allow silent null-coalescing (where a missing `pull_request` object evaluates to null instead of throwing an error, bypassing security gates). 

To mitigate these inherent footguns, the thread surfaced two strict rules for CI:
- **Never interpolate into YAML:** Untrusted input should only ever be passed via `env:` variables or managed through tools that output strict data graphs, like Pulumi or CUE.
- **Require static analysis:** Users heavily recommended `zizmor` for auditing workflows, prompting the tool's maintainer to confirm they are actively adding rules to catch unsound bot-actor conditions like the one Snowflake relied on.

The role of Copilot also sparked a debate about the economics of AI-generated code. Because agents make addressing trivial tech debt practically free, teams are generating and merging low-value refactors—like the PR that introduced this bug—without accounting for the hidden cost of human review. As one user summarized, AI might make developers faster, but relying on models trained on a mountain of historically insecure CI templates means "we're also wrong ~10x as frequently."
