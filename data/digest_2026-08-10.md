**Compressing an agent’s reasoning into friendly prose mid-task is lossy and hides failure.** The piece argues that “humanising” prompts—personas like “I have ADHD” or mandates like ASD‑STE100—don’t just reformat output; they force continuous low‑bandwidth compression alongside core instructions like “solve the task” and “use tools,” dropping detail you’ll never see because the result still reads nicely. It gets worse in multi‑agent setups: subagents summarize for each other, compounding loss, so “Most tests passed” replaces the actionable state you actually want: “5/6 PASS; FAIL: test_cache_invalidation; CAUSE: stale key survives restart; REPRO: tests/cache_test.py:184.”

Humanisation also smooths over the very signals that make agent failures diagnosable—conflicting evidence, unresolved branches, stack traces, token‑window pressure—into bland sentences like “There are a few considerations here.” By contrast, every other engineering system preserves high‑fidelity internals and only transforms at the display boundary: databases vs dashboards, compilers vs IR, APIs vs clients. The prescription: let agents trade precise, machine‑facing state (schemas, diffs, exact errors, confidence, provenance) and only render accessibility and style at the end. “Talk to me like I have ADHD” fits as a renderer, not an operating instruction; the viral “skills” are less a solution than a bug report pointing to where that boundary should live.
