**Treating N‑D arrays as tables with dimension keys turns matmul into a SUM(val*val) JOIN … GROUP BY, so an MLP’s forward pass and autograd compile down to plain SQL.** In this demo, tensors live in Xarray-SQL, and the network trains directly over a tabular view of data.

- Model: 784-196-32-10 (tanh, then softmax), implemented as per-layer weight tables plus bias tables in one Dataset that splits into SQL tables.
- Data path: Fashion-MNIST streamed lazily from an S3-hosted Zarr store (no full in-memory load); an offline synthetic fallback keeps the same pipeline.
- Autograd: built atop Apache Arrow DataFusion’s visitor pattern (inspired by JAX). In this relational-array model the only needed partials are on the diagonal of the Jacobian, making grad, jvp, and vjp row-wise SQL ops.
- Optimization: skipping zero-valued input pixels shrinks the dominant layer-0 join without changing results; measured ~1.8x on real Fashion-MNIST (2.56 -> 1.45 s/step) because background pixels are mostly zero.
- Practical knobs in code: N_SAMPLES=700, TRAIN_FRAC=0.7, LR=0.5, STEPS=60; dependencies are xarray_sql, xarray, numpy, s3fs, zarr.

The author argues this isn’t just a curiosity: if a network is a series of relations and the logical plan is decoupled from the physical layer, training could map cleanly onto distributed backends (e.g., many GPUs) from one global plan. Presented at DataFusion’s showcase; the code is a compact ~446 LOC proof that common geo/climate ops (e.g., regridding as sparse matvec) and NN training can be expressed relationally.

The thread largely explores the theoretical equivalence at the core of the demo: `einsum` and database joins are mathematically identical operations performed over different semirings.

- **Prior art:** Readers pointed to existing explorations of this overlap, including Datalog (Dyna), Apache MADlib, and GraphBLAS-backed databases like TenSQL.
- **Data modeling:** When asked about the ISO standard for multidimensional arrays in SQL (SQL/MDA), the author clarified a key architectural split: they model arrays as standalone tables (following SciDB) rather than treating them as a column data type.
- **Limits of the abstraction:** While commenters praised the elegance of using relational algebra as an intermediate representation to let database optimizers reason over tensor programs, some cautioned about fundamental scaling bottlenecks with natural joins. To map efficiently to modern hardware, one commenter suggested eventually dropping triangular queries or adopting frameworks like Differential Dataflow.

### Show HN: Jacquard, a programming language for AI-written, human-reviewed code

#### [Submission URL](https://github.com/jbwinters/jacquard-lang) | 95 points | by [jbwinters](https://news.ycombinator.com/user?id=jbwinters) | [55 comments](https://news.ycombinator.com/item?id=48894630)

Functions declare their side effects (e.g., (text) ->{net} text) and **the runtime refuses to perform them unless explicitly granted with --allow**, letting reviewers see and control what AI-written code can touch. Handlers are swappable, so the same program can run against the real network, a scripted fake, a recording, or a probabilistic model—turning “what happens if the API flakes out?” into an ordinary test and enabling enumeration of exact probabilities for finite discrete models.

- Algebraic effects with deep, multi-shot handlers make exhaustive search and exact inference library-level features; the Warp test framework layers replay, results caching, and handler substitution.
- Structural, content-addressed identity hashes canonical resolved structure (not source bytes), so renames/formatting don’t trigger recompiles or pure test reruns; only canonical code or dependency changes do.
- Tooling includes a compact .jac surface syntax, an OCaml checker and CPS interpreter, a C-emitting AOT backend (compiling the kernel .jqd carrier), a CLI, a Jacquard-written stdlib, demos, and published binaries for Linux x86-64 and macOS Intel/Apple Silicon.
- Status: 0.1 works end to end but is a research prototype with documented limits; the kernel has 27 forms, uses type-and-effect rows, and offers discrete probabilistic programming as a library.

Designed for AI-written, human-reviewed code, this is especially suited to agent systems where you want capabilities explicit, worlds swappable, and behavior pinned by evidence.

The inclusion of multi-shot algebraic effects drew immediate technical skepticism. Commenters warned that delimited continuations are notoriously difficult for humans to mentally parse, questioning whether LLMs—operating on scarce training data for such niche paradigms—could handle them safely. The author conceded the risk, noting ongoing work to strictly separate one-shot from multi-shot handlers so reviewers can explicitly reject unsafe multi-shot executions, such as duplicate filesystem writes.

On the architectural side, users clarified how the runtime's "world" model distinguishes itself from standard Dependency Injection. While a one-shot effect structurally mirrors a DI lambda, the effect system introduces the core control-flow capacity to abort entirely or resume execution multiple times. Several users praised the mandate to surface all environmental side-effects directly in function signatures (comparing the approach to Jai) and the use of content-addressed AST identity for strict compilation caches (drawing parallels to Unison).

However, the project faced sharp critique over its own legibility. Readers pointed out that a tool explicitly built to make AI-generated code comprehensible to human reviewers undercuts its core premise when its documentation relies heavily on compiler jargon ("kernel," "carrier") rather than clear, real-world examples. Even with perfect explicit syntax, the thread highlighted the enduring limitation of AI-assisted verification: test suites and effect trackers will still rigorously validate a flawlessly executed, but fundamentally backward, logic requirement.
